{# ───────────── B. Features ───────────── #}

Capabilities

What the app covers

Six areas of account management, implemented once so each new Django project does not have to rebuild them.

Authentication

  • Registration with username, email and password validation
  • Login by username or email, case-insensitive
  • POST-only logout
  • Safe redirect handling

Email verification

  • Expiring, single-use tokens stored as hashes
  • Resend flow with a cooldown
  • Handling for unverified accounts
  • HTML and plain-text email templates

Password management

  • Password change for signed-in users
  • Email-based password recovery
  • Session-epoch-aware token invalidation
  • Responses that do not reveal whether an email exists

Profile management

  • Profile information and public profiles
  • Avatar validation, resizing and cleanup
  • Account settings

Privacy controls

  • Per-field visibility for name, email, phone, bio and avatar
  • Public, authenticated-only or hidden
  • Optional integration with an external blocking system

Account lifecycle

  • Deactivation and reactivation
  • Immediate or delayed deletion
  • Cleanup of deleted accounts and avatar files
  • Protection for the last active superuser
{# ───────────── C. Security and reliability ───────────── #}

Security and reliability

Safeguards built into the flows that matter

These are implementation details, not certifications. The app has not been independently audited, and it does not include two-factor authentication or social login.

Backend caveat

Row locking applies where the code uses it and depends on the database. PostgreSQL honours it. Other backends may give weaker guarantees, so test on the database you deploy.

Cache-based rate limiting
Applied to sensitive flows. Limits live in your configured Django cache, so a shared cache is needed across multiple processes.
Session epoch invalidation
An epoch counter on the account lets security-relevant changes invalidate existing sessions and outstanding tokens.
Database uniqueness constraints
Identifier uniqueness is enforced by the database, not only by form validation. A management command checks for identifier collisions.
Transaction-aware operations
Account operations run in transactions, and signals are emitted only after a successful commit.
PostgreSQL row locking
Used in the places where the implementation takes it, to serialise concurrent changes to the same account.
Enumeration-resistant responses
Account recovery and email change respond the same way whether or not an address is registered.
Django system checks
Configuration problems surface through manage.py check rather than at runtime.
Centralised privilege changes
Role and privilege changes go through the service layer, including protection for the last active superuser.

{# ───────────── E. Account lifecycle ───────────── #}

Account lifecycle

From registration to cleanup

Deactivation is reversible. Deletion is a separate path that ends in permanent removal.

  1. 01

    Registration

    Sign-up emits user_signed_up.

  2. 02

    Email verification

    A single-use token confirms the address and emits email_verified.

  3. 03

    Active account

    Profile, privacy and settings are available.

  4. 04a · reversible

    Deactivation

    Emits account_deactivated. Reactivation emits account_reactivated.

    Reactivation page →

  5. 04b · deletion

    Deletion

    Immediate or delayed. Request emits account_deletion_requested; removal emits account_deleted. Delayed deletions are cleaned up by purge_deleted_accounts.

Developer integration

Three touch points in your project

  1. 1.Add the app and point AUTH_USER_MODEL at its user model before the first migration.
  2. 2.Include accounts.urls. It declares the accounts namespace.
  3. 3.Connect receivers to the signals you care about.

Check module paths, the user model name and the available ACCOUNTS_* settings against your copy of the app. The snippet shows the shape of the integration.

Management commands

Operational tooling

Assign a role to an account from the command line.
purge_deleted_accounts
Remove accounts whose deletion is due, including their avatar files.
check_identifier_collisions
Report accounts whose identifiers would collide under case-insensitive matching.

  • account_deleted
